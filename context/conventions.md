# フィーチャーブランチの名前

フィーチャーブランチには、ハッシュやランダムな文字列ではなく、作業の中身が分かる意味のある名前を付ける。

# 最優先事項：コード品質

- 「機能が動くこと」よりも「商用レベルのコード・アーキテクチャ品質」を最優先する。
- 安易なその場しのぎは認めない。動かすためだけのハック、根拠のない回避策、場当たり的な条件分岐を入れない。
- 部分的な実装は認めない。手を付けた機能は、設計・実装・テストまで完結させる。TODO や未実装の分岐を残して先へ進まない。
- 時間や規模が足りない場合は、品質を下げるのではなくスコープを絞る。小さくても完成したものを積み上げる。
- 既存コードが品質基準を満たしていない場合、その上に積み増すのではなく、まず設計を正す。
- 急がない。設計の判断に迷ったら、実装を進める前に相談する。
